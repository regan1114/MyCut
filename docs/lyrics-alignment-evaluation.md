# 歌詞對齊準確度評估

此工具以人工時間標註為基準，評估本機原稿對齊引擎的句子定位率、句子起訖誤差、逐字時間誤差與處理速度。音訊與人工標註由使用者自行準備；目前倉庫中的語音素材是合成語音，不作為真實歌唱準確度基準。

## 準備資料

複製 [`lyrics-alignment-corpus.example.json`](../tests/fixtures/lyrics-alignment-corpus.example.json)，將 `audio` 換成相對於 manifest 的 WAV 路徑，並以人工聆聽結果填入歌詞和時間。音訊需為 16 kHz、單聲道、16-bit PCM WAV，單首不超過 20 分鐘。重複歌詞要逐次標註；每句起點以第一個可聽見的演唱音素為準，終點以最後一個可聽見的演唱音素為準，並在所有樣本使用同一規則。

逐字 `words` 可省略；填入時，`text` 串接後須與該句完全相同，時間須按音訊秒數遞增。請按引擎 token 切分：中文通常逐字；英文依字詞切分，空格和標點也要保留在相鄰 token 的 `text` 中。只有與引擎輸出 token 完全相同的句子會納入逐字誤差統計。重疊合唱可以保留在標註中，工具會照常計算，但目前引擎會將重疊或順序不合的句子列為未定位。

每筆樣本可加上 `language`、`genre`、`vocal` 分類欄位，例如 `zh`、`ballad`、`duet`。使用原創或已取得評估授權的音訊；音訊和逐字標註不要提交到 Git。manifest 可放在專案外的私人資料夾。

## 執行

目前平台尚未建置對齊執行檔時，先依[引擎建置說明](../LYRICS_ENGINE_INTEGRATION.md#建置及封裝)準備本機引擎。

```sh
npm run lyrics-aligner:evaluate -- --manifest /path/to/corpus.json --output /path/to/report.json
```

若引擎或模型不在預設位置，可傳入 `--engine` 和 `--model`。結果會包含整體、語言／曲風／人聲型態分組及逐曲統計，也會保留每句參考時間、實際時間、起訖誤差和模型回報的句子信心值。處理速度以 real-time factor 表示：小於 `1` 代表快於音訊播放時長。

## 指標解讀

- **coverage**：成功定位的句數除以人工標註句數；未定位句也計入分母。
- **起訖誤差**：成功定位句子的人工時間與引擎時間之絕對差，分別回報中位數、P90 和最大值。
- **within100/250/500ms**：起點與終點都在該誤差範圍內的句數。報告另提供 coverage，避免只看已成功定位的句子。
- **逐字誤差**：僅比較人工與引擎輸出字詞數量、文字順序完全一致的句子；其他句子會記為 tokenization mismatch，不混入誤差值。
- **realTimeFactor**：對齊耗時除以音訊秒數；不含載入音訊到 MyCut 時間軸的操作時間。

先建立包含曲風、人聲型態與語言差異的小型基準，再逐步擴充。不要用同一首歌反覆調參後的結果代表泛化準確度，也不要把模型信心值當成已校準的正確機率。
